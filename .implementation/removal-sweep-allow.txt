# removal-sweep-allow.txt — intentional retained executable references to removed artifacts

# Authority: retro-012-017 / BRIEF-LOE-013 (the cross-layer removal-sweep gate).
# Consumed by: scripts/validate-gates.sh check 10 (check_removed_artifact_orphans).
#
# WHAT THIS FILE IS:
#   The ONLY declared input to the removal-sweep gate. It does NOT gate which
#   removals are checked (that is always the git diff — un-forgettable by design);
#   it only ADDS suppressions for executable references a removal INTENTIONALLY
#   retains. A doc-only (.md) reference is allowed by rule and never needs an entry
#   here — entries are for EXECUTABLE consumers (.sh/.ts/.tsx/.js/.mjs/.cjs/.py/
#   .yml/.yaml/package.json) that legitimately keep a reference to a removed file.
#
# FORMAT (one entry per line; '#' comments and blank lines ignored):
#   <removed-artifact-path> | <consumer-path> | <mandatory reason>
#
#   - field 1: the removed file's repo-relative path (as it appeared before deletion)
#   - field 2: the consumer file that retains an executable reference to it
#   - field 3: a MANDATORY free-text reason. An entry whose reason field is EMPTY
#     is itself a GATE FAILURE — a suppression is a documented decision, never a
#     silent one (the judgment-line ethos: the suppression is an agent input,
#     recorded with its rationale).
#
# An executable hit that matches an entry here is downgraded to PASS with its reason
# echoed in the check output. A non-allowlisted executable hit FAILS the gate.
